## v0.1.2 - 2026-11-02

### Added

- In-app release notes. A "What's new" dialog lists the changes since your last version after an update, and Settings → Changelog shows recent releases (built into the app, works offline).

### Changed

- Sync reads your own PRs first and loads review requests only once To review is opened: the newest 100 in the background, with "Load more", a GitHub search as you type, per-stage progress ("Checking my PRs… 40/132") and status checks 4 at a time.

## v0.1.0 - 2026-11-01

### Features

- Bootstrap the desktop workspace, CI, and the unsigned macOS release pipeline.
- Add the SQLite store with migration 0001, a writer thread, a read pool, and repository helpers for every table.
- Add the review message builder, Markdown title escaping, and golden fixtures from the message script.
- Add CODEOWNERS matching, the readiness gate, and the owner decision, including the four parser fixes.
- Add the setup wizard and GitHub GraphQL sync, with keychain fallback and a temp-database override for Linux.
- Add mapping CSV import and export, with replace and merge modes, a dry-run diff, and user-over-imported lookup.
- Add the grouped pull-request list with search, the funnel menu, tri-state selection, and a disabled bulk bar.
- Add projects with auto-link rules and a live preview, manual links by drag and drop or from the project dialog, and Remove/Restore for excluded PRs.
- Fetch ownership inputs (changed files, CODEOWNERS, branch rules, protection, reviews with onBehalfOf, team members) with a cache, and add a PR detail view that shows readiness, owners, and the reasons. A BLOCKED PR with no review decision is Ready only when a code-owner review is known to be pending.
- Sign in to Slack workspaces through the official Slack MCP server (browser OAuth with PKCE and an optional client secret) from the setup wizard or Settings, then request or bump review on Slack from a PR with a message preview; the list shows Requested/Bumped with elapsed time and a link to the thread.
- Request or bump several PRs on Slack at once: one preview with every message grouped by channel and thread, an optional single top-level request per channel or one target channel (DM IDs accepted), paced sends that respect Slack rate limits, and a per-PR result table with Retry failed.
- PR detail Slack panel: the review threads PR-Nexus posted for the PR with replies, authors, and links (cached for 5 minutes, Refresh to re-read), plus an opt-in Find mentions search for the PR link in public channels or also private channels and DMs.
- An update icon appears next to Settings in the sidebar when a newer release is available (or, for dev builds, when the build is behind `main`). Click it for the release link or the update command, or skip that version.

### Added

- Settings → Slack: "Also post bumps to the channel" (review.bump_broadcast, on by default). Off makes bumps thread replies only; the preview says which.
- Settings tabs: Accounts, Mappings (inline edit, reset to imported, CSV import with a dry-run diff, export), Review, Sync and About (paths, keychain explainer, Re-run setup).
- Update available banner and About → Check for updates, from the GitHub releases API with your token; the DMG is downloaded by hand.
- Daily rotating log file with tokens, OAuth codes and secrets redacted before each line is written.
- A hint above the list while no team channel is mapped, plus loading and error states with Try again.
- List keyboard: Esc clears the selection, r requests the selection when there is one, the focused row scrolls into view and is announced to screen readers.
- Mappings: setup step 6 and Settings → Mappings get a Choose file… button that opens the native file dialog (CSV, or All files) and loads the picked mapping CSV for the usual import and validation; the file is read by the backend, so the app needs no file system scope. Pasting a CSV still works.
- Homebrew install on Apple Silicon Macs: `brew install --cask harnesstap/tap/pr-nexus`. Each published release updates the cask in harnesstap/homebrew-tap. Linux CI jobs for pull requests from forks run on GitHub-hosted runners instead of the self-hosted ones, and `app/package.json` now carries the release version.
- Search Slack from the review dialogs: type `#` for channels or `@` for people (a person gets a direct message), with code-owner channels listed first and ID entry kept as a fallback. People search needs the `search:read.users` user scope: add it to an existing Slack app and reconnect.
- Quick status filters above the PR list: Draft, No review requested, CI errors or conflicts, Review declined and Ready to merge. One at a time, with a count on each button; they combine with search and the filter menu, work with Select all, and are remembered per view.
- Add to project in the selection bar (`p`): pick a project or create one from the selection in a single step, with a confirmation toast and the project highlighted in the sidebar. The sidebar's new-project field can take the current selection too. Buttons now carry icons, icon-only buttons have tooltips with a short explanation and their shortcut, dialogs close with an ✕, and text fields no longer spellcheck, autocorrect or autocapitalize.
- Dragging PRs onto a project shows an "N PRs" badge for the whole selection, including everything picked with Select all, and the confirmation toast now has Undo. Undo puts each PR back the way it was: unlinked, linked by a rule (if the rule still exists) or excluded.
- Each PR row shows avatars of the users and teams that still have to review, users first then teams in a fixed order, with a "+N" chip past three and a tooltip listing everyone. Names and avatars come with the sync (no extra request) and are stored in the local database; a reviewer drops off on the next sync after they submit.
- The detail panel's Conflicts card is now a Branch card: it shows whether the branch is up to date with its base, how many commits behind it is, whether an update is required before merging, conflicts (with Resolve on GitHub), or a spinner while GitHub is still checking. Update branch merges the base in or, after a confirmation that warns when other people committed on the branch, rebases onto it. The behind count is fetched only when the panel opens and cached per head and base commit.
- macOS dev: opt-in stable code signing for `bun run tauri dev` (`scripts/macos-dev-signing-setup.sh` plus a cargo runner), so the keychain's "Always Allow" survives rebuilds.
- Live updates: between syncs PR Nexus watches your GitHub notifications (read-only, never marked as read) and refreshes just the pull requests they mention, usually within a minute. Unchanged polls are 304s that do not count against the rate limit. Pending checks are re-read every 90 s while focused (5 minutes in the background), and coming back after a minute away runs an incremental sync. On by default under Settings → Sync; fine-grained and GitHub App tokens fall back to the periodic sync, as the sync details panel explains.
- Detail panel: one prominent "Request review on Slack" button under the merge verdict (shortcut `r`) replaces the small header icon; once a request exists it shows the request summary with Bump. The state pill toggles Draft ↔ Ready for review (plus "Mark ready for review" in the draft box), optimistically with a toast and rollback, disabled with a reason when you can't change it.
- Press `?` for a keyboard cheat sheet generated from the shortcut registry the list uses, and ⌘K / Ctrl+K for a command palette that runs list actions (request review, open in GitHub), switches views and projects, syncs, opens settings and jumps to any PR by number, title or repo. Secondary and tertiary text now meets WCAG AA contrast on the dark theme.
- Projects get a description and JIRA links (keys or URLs; bare keys link once Settings › Review › JIRA base URL is set), shown as chips wherever a project appears. Pull requests get a private note in the detail panel (saved on blur, ⌘↵ or Save) and a star: starred PRs pin to the top, filter with the Starred chip in the toolbar (or Starred only in the menu), and toggle with Shift+S. Each row has a GitHub button (or press o) that opens the PR without opening the panel. Mark ready for review / Convert to draft moved from the header into the merge card, the four summary cards share one size, and the Slack card no longer truncates its channel line. Statuses gain Waiting and Idle.
- Settings → Agents (MCP): an opt-in local MCP server so AI agents on your computer can list and read your projects and pull requests (statuses, notes, stars, Slack requests). It listens on 127.0.0.1 only, needs a bearer token kept in the keychain (copy or regenerate it in Settings), rejects foreign Host and Origin headers, and starts or stops without a restart. Local writes and Slack sends are coming next.
- Requesting review on Slack warns when a PR is still a draft: the single dialog shows a yellow callout with an inline "Mark ready for review" (the same action as the merge card) and the send button reads "Send anyway"; the bulk dialog lists which selected PRs are drafts, badges them, and offers "Mark all ready". Drafts are no longer skipped from bulk requests. Review previews (single and bulk) now carry structured `pr_warnings` (`kind: "draft"`) for other callers such as MCP tools.
- Settings → Agents (MCP): Local writes can now be turned on. Agents can then create, rename, archive and unarchive projects (never delete), add or remove PRs, set JIRA links, and set notes and stars; the list refreshes right away. A new Activity log shows every agent call (time, client, tool, summary, allowed / denied / error), keeps the last 5,000 calls for up to 90 days, never stores note text, and can be filtered or cleared. Slack sends are still coming.
- Agents (MCP): Slack private search (off by default) and new read tools for reactions, channel members, emoji, files, canvases and lists. Workspaces signed in before these scopes existed show "needs new Slack permissions" with a Sign in again button; calls still go to Slack, which answers for itself.
- Agents can propose Slack messages, scheduled messages, drafts and reactions through the local MCP server. Each one waits in Settings → Agents until you approve it, except in channels you list for auto-send; auto-send pauses when the agent read another workspace first. Slack sends is off by default and Slack's replies and errors come back unchanged.
- Agents can search and read Slack through the local MCP server: workspace-aware read tools with qualified IDs, a workspace whitelist in Settings → Agents and untrusted-content marking; replies are otherwise passed through as Slack returns them. Off by default.
- Agent Activity rows for Slack messages, thread replies and reactions now link to the message in Slack ("↗ Open in Slack"), messages read "sent a message in #channel" and thread replies "replied in a thread in #channel".
- Slack sends for agents has three modes: approve everything, fully automatic (no approval), or a channel allowlist (the default, as before).
- Agents whose MCP client supports elicitation now ask you to confirm a held Slack write right in the agent, showing the workspace, channel and exact text. Accepting sends it at once (logged as approved in that agent), declining drops it, and no answer leaves it waiting in PR Nexus. A new "Ask in the agent when it supports it" setting, on by default, controls this.
- Settings → Slack → Message templates: edit the single and batch review-request and reminder texts, and the batch item line, with placeholders ({title}, {url}, {who}, {requester}, {count}, {items}), a live preview, inline validation and Reset to default. The defaults are the previous texts, unchanged.

### Fixes

- Use a dark page background so the setup wizard is readable, and skip GitHub sync in demo mode.
- Bind the Vite dev server to 127.0.0.1 so `tauri dev` finds it on macOS, where localhost resolves to IPv6.
- Every tooltip now uses the app's dark styled tooltip instead of the grey OS one from HTML `title` attributes (list row Slack cell, status pills, repo names, project badges and more). Tooltips render above scroll containers, flip near window edges, and a lint rule blocks new `title` tooltips.
- The sidebar sync status no longer looks stuck on "Syncing… N so far" after the search ends: it shows "Syncing… checking done/total" while it reads PR status, then "Synced". A sync that fails unexpectedly now shows "Sync failed" instead of staying on "Syncing…".
- Clickable elements (row GitHub and Slack icons, sidebar footer icons, tabs, popover actions, copy buttons and more) now show the hand cursor on hover; disabled controls show a not-allowed cursor.

### Fixed

- List every GitHub org the user belongs to, including SAML SSO orgs the token is not authorized for (flagged with an authorization hint); explain disabled Next buttons, drop milestone wording and the placeholder Slack subtitle, clarify the mapping step with a CSV example, always show the Done step, and open a 1280×800 window with a minimum size.
- Count existing projects in the list header, keep empty project sections renamable, open the window maximized then restore its geometry, and hide the native context menu in release builds.
- Bring the PR list in line with the mockup — funnel filter button next to search that closes on Escape or outside click, a Slack status per row (Requested / Bumped with age, greyed Not requested, ↗ link), labelled thread counts and review pills, a Projects empty state with Create project, and Settings moved to the sidebar footer.
- Slack sign-in now waits up to 10 minutes for the browser redirect, shows a countdown with Cancel, and offers "Sign-in timed out, click to retry." on timeout.
- Slack sends no longer show as failed when Slack accepted the message: the official MCP result (JSON text with escaped links and message_context) is parsed, an unreadable result is recovered from the channel or reported as "sent, link unknown" and never retried. Settings checks saved Slack sign-ins at startup and offers Reconnect per workspace, and DM targets read as "DM".
- Name DM targets "DM" in the recent-message warning, and confirm single and bulk Slack sends with a visible toast.
- A mapping CSV merge or replace runs in one transaction, so a failing row leaves the mappings unchanged.
- List shortcuts no longer fire on Cmd+R, Ctrl+F and similar, Shift+x works in the app (the browser reports "X"), and Enter on a button keeps the button's action.
- Merged and closed PRs leave the open list at the next sync (the Archived and closed filter still shows them with a badge), and sync closes their active Slack review requests.
- Esc clears the selection when a row checkbox has focus.
- The Settings mappings filter placeholder is no longer clipped.
- The PR detail Slack card shows the stored last action (Bumped or Requested, like the list row), the permalink and the cached replies even when Slack sign-in has expired.
- GitHub sync no longer fails with "502: github api error" on accounts with many pull requests: search and refresh pages start at 20 PRs, shrink and retry with backoff when GitHub times out, the error names the query that timed out, and the setup wizard offers Retry sync after a failed first sync.
- The app no longer freezes ("not responding") while a sync or any other command waits on GitHub, Slack, the keychain or the disk: every command now runs off the main thread, overlapping sync requests join the one in flight, and a GitHub request times out after 15 s (at most 3 tries and 48 s per page).
- Keychain: a slow answer to the macOS prompt no longer reads as "Keyring unavailable". Keychain calls run on one background thread (one prompt at a time) and never block the window, which shows "Waiting for keychain access" until the prompt is answered (up to 5 minutes). Tokens entered meanwhile are saved as soon as the keychain answers. Deny, a missing keychain and other errors each get their own message and a Retry button.
- Search folds dash variants and full-width characters, and an empty search result says where the query matches (another view, merged or closed PRs, hidden by filters) with a button to go there.
- After Deny on the keychain prompt, saving a token no longer asks the keychain again (and shows another prompt). Tokens stay in memory until Retry keychain access or a restart, and are saved once access is granted.
- Sync now fetches every page of GitHub search results: the 500-PR cap per search is gone, and a search with more than 1000 matches is split by creation date so none are missed. Each page is stored as it arrives, the list header shows "Syncing… N so far" until sync finishes, and a secondary rate limit is waited out instead of failing the sync.
- Route Slack sends by workspace team ID instead of domain, so a channel link carrying an Enterprise Grid org host no longer picks the wrong workspace. Workspaces can be turned off and ordered in Settings → Slack; new requests fall back to the next enabled workspace when Slack says the channel or person is not there, and the picker searches all enabled workspaces at once.
- The generic Participants and Reviewers sections are replaced by one inline row of up to four groups, in order: Author (hidden when it's you), Reviewers (with their status ring, including pending code-owner teams), Assignees, and Commenters (PR and review-thread comment authors, without you or anyone already shown). Empty groups are hidden, each group stacks avatars with +N, and bots are marked in tooltips. Previously the list missed the author and bots and could read "No one yet" on a commented PR.

## v0.6.0 - 2026-11-23

### Features

- To review rows show how long ago the review was requested, including inside a project, and turn amber then red as the wait runs out. The Waiting chip is left off when that age is shown.

### Changed

- The list and sidebar counts reload faster with many pull requests, because only a view with a bump rule looks up which bumps are due.
- After a sync or another refresh, the list redraws only the rows that changed instead of every loaded row.
- The list no longer redraws every 30 seconds while the window is hidden, or on every sync status check that reports nothing new.
- Settings is a shorter list with clearer section labels. Review, Sync, the MCP server, agent activity and About keep every setting, and older links still open the right section. An outdated AI agent config shows once on the list and on Settings until it is updated, in the keychain banner's place so the two never stack. Adding PR Nexus to one AI agent no longer marks the others as adding.
- A failing check chip names the check when one failed ("lint failed", "lint timed out", "lint cancelled", "lint needs action") and says how many failed when several did. The tooltip lists each check and its conclusion, and a click opens that check's log.

### Fixed

- Switching profiles no longer reuses the previous profile's draft state or review preview for a pull request with the same id.
- Adding a pull request to the merge queue or removing it keeps bot comments and bot reviews apart from human ones in the detail panel.
- A pull request read that started before an auto-merge, merge, or merge queue change no longer overwrites that change's result in the detail panel.
- When one card of a CODEOWNERS send fails, the cards already posted leave the dialog, so sending again does not post them twice.
- Choosing All to one channel in the bulk dialog while channel names are still loading no longer brings back the per-team cards with Send enabled.
- Finishing a Slack sign-in reloads the workspace list without token checks, so switches, removals and refreshes made while it waited are kept and the dialog ends sooner.
- In custom views and Bumps due, a search with no results no longer offers Include archived and closed or Reset filters for pull requests outside the view.
- A merge CSV import re-enables a team that was hidden in Settings, as import always writes disabled=0.
- Marking ready or draft, changing auto-merge, removing from the merge queue, and updating a branch no longer report an error when GitHub accepted the change but the read after it failed.
- A fork pull request from a contributor's main branch no longer makes every other pull request into main look stacked on it.
- A review requested again after you reviewed now posts a Review requested notification.
- A view rule with is:closed now lists merged pull requests too, as GitHub does.
- A list in a review note now reaches Slack as bullets, the same as in the preview, instead of a first item glued to the line above.
- A team written with different capitals in CODEOWNERS (for example @Acme/team-a) now finds its saved Slack channel.
- Moving a team mapping to another Slack workspace, in Settings or by merge import, drops the old workspace's team id so requests go to the new workspace.
- A mapping CSV row with more cells than the header is rejected with its line number instead of losing the extra cells.
- The mapping import preview resolves team ids in the workspace column like the import does, and lists a changed team id.
- A removed Slack workspace that is kept for message history no longer shows as Connected, and workspace pickers mark it as needing sign-in.
- Settings → Agents shows the active profile's Slack send policy after a profile switch, so saving there no longer copies the previous profile's policy into it.
- A view under My PRs or To review that asks for merged or closed pull requests with a GitHub-only qualifier, such as is:merged label:bug, no longer comes back empty.
- An open pull request detail no longer refetches from GitHub every 15 seconds; the list reloads only when the live read changed the row.
- The sync status poll counts loaded review requests from the cached list rows instead of reading every pull request with its description, and the view hint reads rows without descriptions.
- A Slack channel entered by its ID now bumps the open review thread in that channel instead of posting a second request that then fails to save.
- Review requests loaded by Load more, the To review search, a GitHub filter or an agent's list are no longer announced as new at the next sync.
- Arrow keys and Esc in a sidebar menu or popover no longer move the list, switch the open pull request, or clear the selection.
- A bulk Slack message that was posted but could not be saved for one pull request is now reported as sent, and the other pull requests in it stay tracked, so Retry failed no longer posts it again.
- Switching profile while the To review tab led a sync no longer waits for a whole My PRs pass to finish.
- Focusing the window or saving new sync intervals now moves the next scheduled sync at once, and saving review preferences repaints the menu bar and dock counts.
- Sending a single Slack review request now checks the pull request again first, so one merged, closed, or blocked while the dialog was open is not posted.
- A pull request opened from a notification or the menu bar is marked read, like one opened from the list.
- Review requests asked for by an agent no longer stay loading when the sync fails or pauses on the rate limit; To review shows the error instead.
- A list reload counts each sidebar view once instead of twice.
- The single-PR review dialog no longer posts a bump or request other than the one its preview showed; it asks to preview again instead.
- Clearing a "Sync every" field in Settings → Schedule leaves it empty instead of showing 1, and Save asks for a value instead of failing.
- The list refreshes after an agent sends Slack review requests, whether auto-sent, approved in the agent, or approved in PR Nexus.
- Load more review requests keeps To review loading until the new rows arrive, instead of showing them up to 15 seconds late.
- Agent review requests over several channels look up each pull request's owners on GitHub once per channel it goes to, not once per channel for every pull request.
- A pull request whose code-owner status cannot be resolved is no longer checked again on every sync, so other pull requests get their turn and the list stops refreshing for nothing.
- Startup no longer waits for an unanswered keychain prompt while setup is in progress.
- When a GitHub request hits the 15 s client timeout, sync now retries with a smaller page instead of failing.
- A Slack review request whose connection drops mid-send is no longer posted a second time.
- A deleted, transferred or SAML-blocked pull request no longer makes every status and refresh pass fail.
- A spent GitHub rate limit now reports its real reset time and is no longer retried like a secondary limit.
- Connect GitHub and the setup check now read the gh CLI account that is active now, so a recent `gh auth switch` is picked up.
- Review stats measure the wait from creation for a pull request opened ready and later converted to a draft, and a pull request that is a draft again no longer counts as waiting for review.
- The review stats repository or organization menu keeps showing the chosen scope when the new period has no pull requests in it, instead of reading "All tracked repositories" while the numbers stay filtered.
- In setup, Copy & open now copies the device code, and I've authorized says when GitHub has not confirmed the sign-in yet.
- Creating a profile that fails while copying settings or secrets no longer leaves a half-made profile behind, so the same name can be tried again.
- Opening To review, listing or refreshing Slack workspaces, and connecting Slack read the database and keychain on background threads, so a slow read or a keychain prompt no longer holds an app worker.
- A sync between a failed close and its retry no longer forgets the posted close comment, so the retry does not post it twice.
- A live update for an old closed pull request no longer brings it back into Archived and closed until the next sync.
- Sync closes the review requests of merged and closed pull requests in one write, and no longer fails when one was already closed by a merge from the detail panel.
- After a pull request's detail was opened while CI was pending, a later sync now shows finished checks instead of keeping the row on pending.
- After picking another channel or person in the review dialog, Send waits for that target's preview and can no longer post to the previously shown channel.
- Turning off Slack reads for agents now also stops Slack private search and Slack sends, as Settings → Agents shows.
- The detail panel's Slack card shows a request or bump right after it is sent, so Bump is no longer offered again at once.
- The agent list_prs tool's repo filter matches a bare repository name, as its description says, instead of returning nothing.
- In Settings → Mappings, a channel name read from Slack after an ID is entered no longer wipes edits made meanwhile or reopens a row that was cancelled or saved.
- Agent prompts accept a pull request link with a fragment, query or /files path, and no longer take a non-GitHub link for a GitHub pull request.
- Agent activity no longer records the link text an agent passed to remove_jira_link when the project has no such link.
- In To review, choosing No team together with a reviewer team no longer limits the GitHub search to that team, so older review requests with no team are found too.
- A project's JIRA chips in the list open their ticket again instead of doing nothing.
- Deleting the custom view that is open returns to the view it was nested under, instead of listing every pull request under "Pull requests".
- Resetting a renamed default view or duplicating a long-named view no longer stops every later sidebar change from being saved, and a failed save now says so.
- A new custom view no longer opens with the search, sort and filters of a view deleted before it.
- A low GitHub rate budget pauses scheduled sync and live updates only until it resets, instead of until the next manual refresh, and the "Rate limited · resets" time is shown in local time.
- Clicking a notification posted before a profile switch no longer opens an unrelated pull request of the new profile.
- Marking read, snoozing, unsnoozing or muting pull requests updates the menu bar counts and dock badge at once instead of at the next sync.
- A locked keychain after sleep no longer stacks macOS prompts. One request is shared, secrets stay in memory, and a refused or locked keychain waits for Retry.
- The first keychain read at launch can prompt at once, and saving a credential is no longer stuck behind a silent keychain call that can stall for tens of seconds.
- A render error shows a short error screen with Reload and Copy details, instead of a blank window. The failing-check chip and the review-request age ignore malformed cached fields instead of crashing the list.
- Fix a blank window on macOS caused by two files whose names differ only by case.
